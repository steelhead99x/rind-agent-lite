# rind-results

[steelhead99x/rind-results](https://github.com/steelhead99x/rind-results)
holds measured rind results and this fork's quests. Read its
`AGENTS.md` and `CONTRIBUTING.md` first. Where this skill and that repo
disagree, the repo wins. `upstream.txt` here records the files this
skill was checked against. The `results-drift` workflow opens a PR when
any of them changes.

## Results

A new publish is one directory, as `results/README.md` says:

```text
results/<host>/<upstream-sha>/          or  results/<host>/<upstream-sha>-<label>/
    <host>.json   schema 1, median of the runs
    meta.json     provenance (upstream sha, patches, runs)
    NOTES.md  run.log  raw/  RESULTS.md
```

- Three runs per set. Known-answer checks pass before any timing.
- Never edit, regenerate, or re-measure a published number or raw run.
  Historical trees stay where they were published.
- A gap is another library beating rind by more than 10%. Each gap
  needs an entry in that board's `gaps.toml`, with a `quest` or a
  `reason`.
- `cargo xtask ci` is the gate. It includes `cargo verify`. Run it
  before pushing.

## Quests

`quests/qNNN-<slug>.md` files, indexed in `quests/README.md`. Each
file's frontmatter has:

```yaml
id: Q010
title: "..."
priority: P1          # P0..P3
hardware: [esp32-s3]  # esp32-s3, nrf52840, rp2040, efr32mg24, host:<name>, none
size: M               # S, M, L
status: open          # open, claimed, done, dropped
claimable_by: maintainer
```

- The file is the spec. Its issue, `[QNNN] <title>`, is generated by
  `quest-sync`. Edit the file, not the issue.
- Only the maintainer claims a quest while `claimable_by: maintainer`.
  Otherwise leave a comment or open a PR with results.
- These quests are not rind's `quest/` tree. Only kixel-ai/rind's
  maintainer writes that tree.
